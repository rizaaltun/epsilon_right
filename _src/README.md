# Site source (`_src/`)

The site's pages are generated from the content in this folder. GitHub Pages
does not publish folders whose names start with `_`, so nothing here is served.

```
_src/
  build.py              build the site; --check compares with the files on disk
  sitegen/              page renderers (Python standard library only)
  content/
    settings/site.json  footer details, e-mail, social links, book categories
    books/<slug>.json   one file per book  -> /books/<slug>/
    authors/<slug>.json one file per author -> /authors/<slug>/
    pages/<path>/       every other page: index.json + index.html (<main> fragment)
  tools/                one-off migrations that created content/ from the export
```

## Building

```bash
python3 _src/build.py --check   # writes nothing; exit code 1 if any page would change
python3 _src/build.py           # writes changed pages, removes pages of deleted books/authors
```

`--check --show <path>` prints where one file differs.

## What the build generates

| Output | From |
| --- | --- |
| `books/<slug>/index.html` (268) | `content/books/<slug>.json` |
| `authors/<slug>/index.html` (59) | `content/authors/<slug>.json` + the books whose author has that slug |
| `news/<slug>/index.html` | `content/news/<slug>.json` (body in Markdown, see `sitegen/markdown.py`) |
| `fairs-events/<slug>/index.html` | `content/events/<slug>.json`; upcoming until the end date has passed |
| `publishers/<slug>/index.html` | `content/publishers/<slug>.json` + the books whose `imprint` matches |
| `services/<slug>/index.html` | `content/services/<slug>.json` |
| `blog/<slug>/index.html`, `blog/feed.xml` | `content/blog/<slug>.json` (`sitegen/blog.py`); `/blog/` and the menu links appear once there is a post |
| `catalogues/<slug>/index.html` | `content/catalogues/<slug>.json` + its PDF; reader images per `assets/catalogues/readers.json` (`sitegen/catalogues.py`) |
| English sample readers on book pages | a book's `english_samples` → preview PDFs in `samples/` (not published); page images per `assets/images/samples/readers.json` (`sitegen/samples.py`, previews made with `tools/make_sample_preview.py`) |
| every other page | `content/pages/<path>/index.{json,html}`; editable texts in `texts.json` next to it |
| `assets/meta.json` | all books (used by the /books search and filters) |
| `sitemap.xml`, `robots.txt`, `llms.txt`, `404.html` | all pages / settings (`sitegen/seo.py`) |

Every page gets a meta description, canonical URL, Open Graph/Twitter tags and
schema.org JSON-LD (Book, ProfilePage, NewsArticle, Event, Organization, Service,
DigitalDocument, BreadcrumbList…). Any item's `seo_title` / `seo_description`
override the defaults, which are derived from its content.

Book order everywhere follows each book's `order` field. A book links to its
author's page when the author name's slug matches an author file.

Page fragments contain slots that the build fills from content, so a book
changed in one file updates every page that shows it:

- `<!--@cards select="RULE" wrap=li|none [article="…"]-->` a run of book cards
- `<!--@count select="RULE"-->` the number of books selected
- `<!--@news-cards [limit=N]-->`, `<!--@news-count-->` news cards / count
- `<!--@event-sections-->`, `<!--@event-aside-->` fairs lists / home hero card (a fair or the latest news)
- publisher and author cards, counts and filters: see the list in `sitegen/pages.py`

Before the slots, a fragment is rendered as a small template (`sitegen/template.py`):
`{{key}}` comes from the page's `texts.json`, `{{stats.items}}` / `{{contact.…}}` from
`content/settings/`, with `{{#each}}`, `{{#if}}` and filters such as `|md` and `|path`.

`RULE` is `all`, `catalogue:<slug>`, `imprint:<name>`, `category:<slug>` or
`list:<name>` (a hand-picked list in the page's `index.json`, e.g. the home
page highlights).

"More in this category" on a book page shows the next 8 books in the same
category, wrapping round to the start of the list.

Covers: a book stores the path of its largest WebP variant; the `srcset` is
built from every `<stem>-<width>.webp` found in `assets/images/covers/`.

Set `SITE_TODAY=YYYY-MM-DD` to build as of another date (fair status depends on it).

## Phase 1 guarantee

The migration was verified by `python3 _src/build.py --check`: all 358 pages
and `assets/meta.json` are regenerated byte for byte identical to the export.
Quirks of the export were therefore reproduced on purpose, not fixed.

## Known issues kept as-is (to fix in phase 2)

- Fixed in the publishers step: `/authors/` listed 24 of 59 authors behind a
  "Load more" button that did nothing, and `/authors/`, `/publishers/` and
  `/representations/` showed stale title counts (e.g. Epsilon 22 instead of 101).
- The search, sort and filter controls on `/authors/` and `/publishers/` are not
  wired up (site.js only implements them on `/books/`).
- One author appears under three spellings: Şöhret Doğruyol Sağbaş / Şağbaş / Şabaş.
- The "Okuyan Koala" imprint (3 books) has no publisher page.
- Fixed in the SEO step: footer category links used slugs that don't exist; "worlwide"
  (94 books) and other rights typos; rights-sold languages mixed Turkish and English.
- Footer links to `/privacy-policy/` and `/terms/` return 404.
- Fixed in the page-texts step: the contact page "View on map" pointed to
  `https://maps.example.com`; it now searches the office address on Google Maps.
- Services pages and cards use the template's abstract placeholder images (scene-0x.jpg).
- Fixed in the news/events step: the fair page linked to `https://example.org` and
  showed template placeholder images as its gallery; Frankfurt (7–11 Oct) still said
  "Upcoming"; the Publishers Weekly article used a one-off layout.
- Book pages without a cover give hero loading hints to the first card in the rail.
- Three news pages don't lazy-load the logos; `<title>` escaping is inconsistent.

## Superseded workflows

`scripts/optimize_site.py` (cover WebP variants) and `scripts/build_catalogue_readers.py`
(catalogue reader images) are now done by the build (`sitegen/covers.py`,
`sitegen/catalogues.py`, same sizes and quality); `scripts/import_catalogue.py` was a
one-off import. Their workflows patched generated HTML and have been removed; the
scripts are kept for reference.

- Fixed in the catalogues step: the two full catalogues used a plainer one-off page
  layout, and "More in Books & Publications" showed template placeholder covers.
